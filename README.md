**关于 🟡：** 仓库里带参考解（文件头有完整思路）的题记 🟡，**不计入已刷数量**。

这条规矩是为了让这个仓库经得起别人翻——面试官点开 commit 记录时，看到的是你真走过的路。

## 怎么用这个仓库

1. **限时 25 分钟**独立写，写不出来就停，不要死磕；
2. 看题解，**只记思路不抄代码**；
3. 关掉题解**重写一遍**，能独立写出才算过；
4. 按下面的格式提交，commit 信息里带耗时。

```bash
git add .
git commit -m "feat(hash): 0001 两数之和 15min"
git push
```

commit 类型：`feat` 新题通过 / `fix` 订正旧题 / `docs` 笔记 / `refactor` 重写。

## 题目文件模板

每个文件的开头写清四件事，缺一不算完成：

```python
"""
0001. 两数之和  Easy
https://leetcode.cn/problems/two-sum/

思路：...
复杂度：时间 O(?)  空间 O(?)
易错：...
"""
```

- 带 `🟡` 的题，`思路 / 复杂度 / 易错` 已经写好了——**先只看「思路」三个字后面的两三行，然后合上文件自己写**；
- 带 `⬜` 的题，文件头里只有三条**递进式提示**，不给答案，卡住时逐条看。

## 跑一遍所有题

```bash
python run_all.py
```

输出会把每题标成 `PASS`（自己跑通了）/ `TODO`（还没写）/ `FAIL`（写了但没过）三类，最后给一个汇总。
交作业、复盘、或者想确认「今天到底做出来几道」的时候跑一下就行。
